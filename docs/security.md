# 信任边界、配置与敏感材料

## 1. 要解决的问题与前提

本项目主要减少以下操作和路由错误：误用通用代理、SSH 中断后继续使用失效端口、出口与预期不一致、应用忽略代理变量、不同启动入口配置不一致。

成立的前提是宿主操作系统、系统管理员、部署代码和上游代理可信，应用通过已验收入口启动，使用者不主动从其他宿主接口绕过限制。周期采样的时序与容错窗口也是方案的一部分，见 [状态机](architecture.md)。

它不是用于运行任意恶意代码的完整安全沙箱。固定出口也不保证账号、额度、区域访问或服务方风控结果；这些需要各自的真实请求和服务要求验证。

## 2. 能力与不可外推的结论

| 控制 | 直接作用对象 | 可验证结论 | 不能外推 |
| --- | --- | --- | --- |
| 专用 listener | 进入该入口的流量 | 出站配置固定为指定节点 | 所有应用已经使用它 |
| 三目的地探测 | 每轮发出的三个 HTTPS 请求 | 该轮采样满足 IP/国家/API POP | 每个目的地、每个时间点出口都相同 |
| gate | 接入它的 TCP/UDS 转发 | 按完整状态机开关监听和既有连接 | 任何探测错误马上切断；前两次瞬时失败仍接受新连接 |
| namespace | 经 wrapper 启动的进程树 | 在该空间中普通外网直连应不可用 | 宿主上所有进程、所有编辑器流量或完整文件访问被隔离 |
| 代理变量 | 会读取这些变量的网络库 | 指向了指定代理 | 程序不能忽略变量，或所有协议都已保护 |
| AdsPower profile | 该浏览器环境 | 按配置和实测使用代理及浏览器参数 | 宿主全局断流，或 HTTP 页已证明 DNS/WebRTC/UDP/IPv6 无泄漏 |
| 旧 local-only 补丁 | 特定扩展版本的远程会话 UI/backend | 该识别版本对应入口被改写 | IP 防火墙或未来版本自动兼容 |

CLI、Claude 图形插件、终端模式、后台 launcher、VS Code Extension Host、webview、Codex app-server 和浏览器必须分开核验。当前 Codex 的代理覆盖不等于 Claude 的 namespace 能力。

## 3. 宿主权限通道

Linux 根文件系统仍主要以可写方式映入。部分控制路径被保护不意味着工作目录、HOME 中的数据和所有依赖不可访问。任何未遮蔽的宿主文件系统 Unix socket、已存在的控制通道或额外设备权限，也应纳入部署者的权限审查。

可选固定 SSH relay 只限制初始连接目标为指定主机的 SSH 端口；一旦认证成功，目标账户可执行宿主命令，其网络不再由原 namespace 约束。默认不启用这些 relay，启用时必须把它视为可信宿主管理能力，不能宣称“所有 agent 命令绝不可能绕过 gate”。

R:17898 只监听 loopback，但同机其他用户可能使用它。Unix socket 有用户文件权限限制。多用户主机如果要求对代理调用者做强身份隔离，需要额外方案；仅将地址写成 127.0.0.1 不解决跨用户授权。

## 4. 可选 host-runner

broker 接受预定义 profile ID，不接受任意命令字符串；校验 Unix peer UID，约束 command、cwd、timeout、环境和可选文件哈希。任务使用空环境及受限地址族的 transient systemd service，保留必要设备视图。

这些过滤依赖目标系统支持，必须现场验证。profile 本身、脚本、解释器、可写依赖和设备访问仍可信；不能通过加任意 shell、SSH 或自由参数入口来“方便使用”。示例策略只提供测试 profile，不代表生产实验策略已经批准。默认核心安装不启用该组件。

## 5. TLS、DNS、协议与本机代理

HTTPS 验证应保持开启。示例显式设置 `http.proxyStrictSSL=true`；不要使用 `-k` 或 `NODE_TLS_REJECT_UNAUTHORIZED=0` 来掩盖证书错误。需要自定义受信任 CA 时按实际产品和操作系统的信任配置处理，并记录来源。

curl 的目标 HTTPS 经 HTTP CONNECT 上游，采样请求的目标域名解析通常由代理链完成；但代理服务器自身的解析、订阅刷新、Windows DNS、浏览器 WebRTC/UDP、扩展自有网络栈属于其他路径。文档只对已经验证的链路作结论，不承诺全机 DNS 都经过 guard。

固定出口前面可以有传输节点，但传输节点只能帮助连接住宅代理，不能在住宅代理失败后取代最终出口。DNS、TUN 和系统代理不能简单复制他人整份配置：必须与本机已有网络共存并单独验收。

## 6. 什么应入库，什么留在私人环境

| 应共享 | 应私人保存 |
| --- | --- |
| 实现源码、依赖声明、构建命令、配置 schema、无凭据示例、测试 | 代理密码/订阅/controller secret、Claude/Codex 认证、Cookie、SSH 私钥、浏览器 profile |
| 脱敏版本与测试范围、缺件、复现步骤 | 实际服务器地址映射、私人任务策略、完整日志/进程参数/环境转储 |
| 样例参数的解释与受限输入范围 | 已渲染部署清单及其真实参数 |

不要将“保护凭据”误解为不能共享合法的配置接口、依赖清单或包含配置读取逻辑的源模块。Windows 精选导出会列出遗漏项，维护者应逐项审查后恢复需要的实现与模板，而不是把带真实口令的原配置直接提交。

`.gitignore` 和常见秘密格式扫描是检查手段，不能证明没有秘密。提交前审阅 `git diff --cached`，避免在整个 HOME 上执行收集或 `git add -A`。导出副本不自动作为 Release 发布。

已有 Git 历史没有重写，当前脱敏不能清除旧提交。发现真实凭据应先轮换，再单独制定历史清理；普通文档维护不需要强推或删除已有分支。
